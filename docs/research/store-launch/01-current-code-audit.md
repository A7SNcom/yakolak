# تدقيق المصدر الحالي

المرجع الثابت وتاريخ الفحص في [README](README.md). مواضع الأسطر التالية تخص ذلك الالتزام فقط؛ يتغير رقم السطر مع التعديلات. الدليل الآلي يحتفظ ببصمات الملفات لتجنب تطبيق استنتاج قديم على نسخة أحدث.

## ما هو المشروع فعلًا؟

| المكون | الدليل | الحكم |
| --- | --- | --- |
| المحرك | `project.godot`؛ `scripts/godot-flash-build.sh:4–6` | GDScript، إعداد 4.7، والبناء مثبت على Godot 4.7.1 |
| نقطة الدخول | `scenes/intro.tscn:3–43` | مشهد واحد يربط المقدمة والإعداد واللعب والاتصال والتشخيص |
| التصدير | `export_presets.cfg` | preset واحد اسمه Web؛ لا iOS/Android |
| العرض | `project.godot:24–30`؛ `scripts/visual_polish.gd:30–36` | Compatibility، حتى 60 FPS، الظلال 4096 وMSAA 4X يضبط وقت التشغيل |
| الواجهة | `ui/visual-setup.mjs` وCSS؛ `scripts/session_setup_visual.gd:49–140` | Godot يملك الطاولة والكاميرا؛ DOM يملك المدخلات والقوائم |
| اللعب | `scripts/game_rules.gd` وسلسلة `gameplay_*.gd` | قواعد وعرض محليان موجودان؛ ليسا دليل قبول جوال |
| الشبكة النشطة | `scripts/online_session_trystero.gd:33–59`؛ `ui/online-trystero.mjs:1–57` | Trystero 0.26.0، WebRTC وNostr؛ ليس HTTP إلى `/api/rooms` |
| السلطة | `ui/p2p-authority.mjs:20–60` | حالة معتمدة في ذاكرة متصفح المنشئ، وتستورد منطقًا من `api/room-state.js` |
| CI | `.github/workflows/online-build-publish.yml` | يبني Web وينشر Pages؛ لا CI لحزم المتاجر |
| القبول الفعلي | `docs/online-acceptance.json:1–13` | `blocked`، لا أجهزة فعلية مسجلة؛ تفويض نشر للاختبار فقط |

**التمييز المهم:** مجلد `api/` ليس كله ميتًا: ملفات التحولات والقواعد تستوردها سلطة P2P وتدخل حزمة المتصفح. أما استضافة المسارات القديمة وقاعدة Turso فليستا خدمة الغرف النشطة في Pages. لا تحذف `api/room-state.js` بحجة عدم وجود backend، ولا تنشر الخادم التاريخي ظنًا أنه مسار الإنتاج الحالي.

## حصر الاعتماد على المتصفح

يوجد 80 ملف GDScript مباشرًا في `scripts/`، منها 71 يذكر `JavaScriptBridge`. العدد **ليس 71 عطلًا**: جزء كبير قياس وتشخيص وسمات DOM داخل حراسة `OS.has_feature("web")`. يلزم تصنيف الاستدعاء قبل نقله:

| الفئة | أمثلة نشطة | التصرف عند التصدير الأصلي |
| --- | --- | --- |
| وظيفة واجهة | `session_setup_visual.gd`؛ `win_tutorial.gd` | نقل الأوامر والنصوص والمدخلات إلى Control/CanvasLayer مع نفس الشكل |
| اتصال وسلطة | `online_session_trystero.gd`؛ `online-trystero.mjs`؛ `p2p-authority.mjs` | adapter جديد؛ محرك Godot لا يشغل سلطة JavaScript تلقائيًا |
| تخزين واسم اللاعب | `visual-setup.mjs:138–140,500–512` | ملف محلي/خدمة هوية ضيف؛ ترحيل اختياري لا يفترض وصول التطبيق لمخزن Safari |
| روابط ومشاركة | `online_session_hardened.gd:146`؛ `visual-setup.mjs:580` | مشاركة النظام، deep links، تحقق الرابط والمدخلات |
| قابلية وصول | `browser_verification_bridge.gd`؛ سمات ARIA في الواجهة | اختبار تمثيل فعلي على VoiceOver/TalkBack؛ لا تعد السمات وحدها قبولًا |
| reduced motion | `session_setup_visual.gd:503–504`؛ `gameplay_reduced_motion_parity.gd` | مصدر تفضيل النظام/إعداد محلي؛ الحراسة الحالية لا تحقق التكافؤ الأصلي |
| تشخيص/اختبار | `diagnostics_gate.gd`؛ `online_resilience_test_bridge.gd` | اجعل سياسة release صريحة مع بقاء سلوك اللاعب متسقًا |

في `session_setup_visual.gd:65–90` تُخفى البطاقة القديمة، وتُرسل إشارة الظهور إلى الواجهة. وفي `105–114` تتوقف دالة إرسال الإشارة إذا لم تكن المنصة Web. لذلك وجود شاشة GDScript قديمة تحت الوراثة لا يثبت وجود fallback مكتمل في النسخة الأصلية. كذلك `host_match()` يرسل `online_unavailable` خارج Web صراحة. هذا سبب رفض عبارة «نضيف preset ونرفع» كخطة تنفيذ.

## الموجود الذي يجب الحفاظ عليه

- مصدر القواعد `rules/yakolak-rules.json`: 2–4 لاعبين، 36 قطعة، 9 خانات، خيارات فوز المباراة 3 أو 5، الدور 30 ثانية، الاستمرار 10 ثوان، تفكير البوت 650ms. هذه قيم العقد الحالي؛ لا تنسخ ثوابت قديمة من أسفل سلسلة الوراثة بدل المسار النشط.
- `rules/win-presentation.json`: البرج = الأحجام الثلاثة من لون واحد في خانة واحدة؛ الدرج = أحجام متصاعدة أو متناقصة على خط؛ السطر = حجم ولون متطابقان على خط. يحتمل أن تحقق حركة نمطين؛ لا تخمن النوع من عدد القطع.
- أسماء الفائز من اللاعب الفعلي، ونصوص المالك كما هي؛ لا يعيد النقل صياغة القواعد أو مسميات الفوز.
- منع الحركة خارج الدور، ملكية المقاعد، `epoch`، التحقق من الإصدار، هوية الحركة وعدم تكرارها، تجميد الدور عند الانقطاع؛ راجع سلطة P2P واختباراتها.
- استمرارية الكاميرا والأحجار والألوان وإلغاء callbacks القديمة كما يفرض `AGENTS.md`؛ نقل الواجهة لا يبرر إعادة تصميم التجربة.
- تعليم الفوز موجود (`scripts/win_tutorial.gd` و`gameplay_tutorial_showcase.gd`) وزر الصوت موجود (`gameplay_session_ui.gd:227` و`gameplay_interaction_feedback.gd`). النقص تكافؤ الجوال واستمرار الإعدادات، وليس اختراع شرح أو زر كتم جديدين.
- معالجة safe area موجودة جزئيًا في `turn_clarity_hud.gd:314` و`gameplay_turn_transition_stale_safe.gd:348`. يلزم توسيع القبول لكل النوافذ ولوحة المفاتيح، لا ادعاء أنها غائبة بالكامل.

## حدود الثقة والتأكد التالي

حالة `docs/online-acceptance.json` حقيقة محفوظة، لكنها لا تصف كل تجربة شخصية خارج المستودع. اختبار browser contexts أو headless لا يساوي جهازين ولا binary متجر. وجود 108 ملفات في `tests/` لا يعني 108 نجاحات؛ منها probes وعقود نصية واختبارات مسار HTTP تاريخي. لا تنقل نتائج README القديمة كأنها تحقق هذه الجولة.

الفحص لا يثبت تسرب بيانات فعليًا، أو مخالفة قانونية نهائية، أو تعطل native على جهاز بعينه؛ يحدد مواضع تحتاج إثباتًا. لا نملك حسابات App Store Connect/Play Console أو قياسات هواتف أو رخصًا خارج المستودع. كل ذلك مطلوب في بوابات القبول قبل الرفع.
