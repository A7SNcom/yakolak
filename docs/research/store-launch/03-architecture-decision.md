# قرار المعمارية وعقد النقل

**الحالة: مقترح غير معتمد.** لا إنشاء تطبيق أو إضافة dependency أو خادم ضمن جولة البحث. المهمة `YKL-004` توثق القرار بعد التجربة وتذكر البدائل المرفوضة وقياساتها.

## مقارنة الطرق على هذا الكود

| المسار | ما يعاد استخدامه | العمل الناقص | المزايا والمخاطر | القرار المقترح |
| --- | --- | --- | --- | --- |
| Godot Web داخل Capacitor بأصول محلية | DOM وCSS وGDScript وJS authority وTrystero | shell أصلي، scheme، lifecycle، مشاركة وروابط، ملفات متجر | أقل إعادة كتابة؛ تبقى تكلفة WebGL/WASM وقيود WebView؛ يلزم POC | أول تجربة 3–5 أيام |
| Godot export أصلي | الطاولة والموشن والقواعد وبعض HUD | إعادة واجهة DOM، التخزين، sharing، الشبكة والسلطة | أقرب للمحرك على الجهاز؛ تكلفة أكبر ولا ينقل JavaScript تلقائيًا | بديل إذا فشلت التجربة أو فضّله المالك |
| غلاف يفتح رابط Pages البعيد | الموقع كما هو | يعتمد على الإنترنت والإصدار البعيد | ضعف offline وتطابق النسخة المراجعة؛ لا خطة إصدار موثوقة | مستبعد من التوصية |
| PWA فقط | الموقع | تحسين تثبيت وتجربة الويب | قناة اختبار وتوزيع ويب؛ ليست إدراجًا في App Store | يستمر Pages بقناته الحالية |
| إعادة كتابة Unity/Flutter/React Native | أصول محدودة | إعادة محرك وتجربة واسعة | مخاطرة لا تبررها حاجة مثبتة | خارج النطاق |

هذه مقارنة هندسية. Godot يوصي بالنسخ الأصلية للأداء مقارنة بالويب [S31]، بينما Capacitor يدعم بناء ألعاب WebGL [S33]. الترجيح لياكلك يوازن هذه النقطة مع الاعتماد الوظيفي الحالي على DOM وJS. لا يوجد اختبار حتى الآن يثبت أداء wrapper لياكلك.

## بوابة التجربة الأولى

ينفذها المطور لاحقًا على **هاتفين فعليين**، آيفون وأندرويد، بملفات محلية مثبتة. مسارات قبولها في `acceptance-template.json`:

- تثبيت نظيف وفتح مع وضع الطيران قبل أول تشغيل؛ الوصول لإعداد محلي وبوتات والشرح، دون اعتماد على CDN/Pages.
- MIME الصحيح لـWASM، تحميل PCK، origin آمن للـ`crypto.subtle`، وتوافق `RTCPeerConnection`. لا تستخدم `file://` عشوائيًا ولا تعطل ATS/TLS عالميًا.
- لا تحوّل مشاركة الغرفة إلى رابط `capacitor://localhost`؛ الرابط العام يبقى رابط الدعوة المسموح، وتُحوّل قيمته إلى التطبيق عند فتحه.
- لوحة مفاتيح عربية، تحديد الألوان، pointer/canvas، تغيير المقاس، كتم الصوت، صوت بعد interruption، background ثم foreground، WebGL context loss.
- قياسات الذاكرة والأداء ومباراة فعلية 20 دقيقة، ثم اختبار WebRTC بين شبكتين. لا يعد فحص `typeof RTCPeerConnection` اتصالًا ناجحًا.
- لا `server.url` للإنتاج؛ إعداد Capacitor نفسه يصفه بأنه للتطوير/live reload [S32]. حزمة الألعاب وواجهة إعدادها ومواردها محلية وثابتة لكل build.

**النجاح:** كل المسارات الأساسية تعمل دون حيل تستثني المراجع؛ توثيق الجهاز/OS/build والقياسات. **الفشل:** شاشة سوداء، context loss متكرر، حرارة/ذاكرة غير مقبولة، أزرار غير قابلة للمس، أو تعذر تصحيح دورة الحياة ضمن الوقت المحدد. عندها لا نستمر في إصلاحات غلاف غير محدودة؛ نوثق سبب التحول إلى native ونقدر النقل.

نجاح التجربة ليس موافقة متجر. إن ورد رفض 4.2 لاحقًا، راجع جودة وقيمة التجربة أولًا؛ لا تفترض أن إعادة الكتابة تحل السبب دون قراءة رسالة المراجع.

## تصميم فصل الخدمات للمسارين

لا نعيد كتابة قواعد الفوز. نفصل حدود المنصة بمواصفات صغيرة؛ الأسماء التالية **مقترحة وليست ملفات موجودة**:

| الخدمة المقترحة | العقد | web wrapper | Godot أصلي |
| --- | --- | --- | --- |
| `ProfileStore` | قراءة اسم ضيف، حفظ اختياري، مسح محلي | storage داخل التطبيق مع version | `user://` وConfigFile/JSON |
| `SessionTransport` | create/join/move/continue/rematch/leave + snapshot/error | adapter لـTrystero الحالي | native adapter يُحسم أدناه |
| `PlatformLifecycle` | pause/resume/process death/audio interruption | plugin lifecycle + events | notifications الأصلية + hooks النظام |
| `InvitationService` | parse/validate/share/join link | native share وapp URL events | plugin مشاركة وروابط أو رمز يدوي |
| `PrivacySupport` | open policy/support/licenses + clear local data | صفحات مضمّنة/روابط عامة | واجهة Control مكافئة |
| `AccessibilityPreferences` | reduced motion/contrast/user preference | bridge النظام وإعداد واضح | مصدر النظام/واجهة محلية بعد التحقق |

مثال عقد تصوري للتسليم، لا ملف autoload جاهزًا:

```text
SessionTransport
  capabilities() -> { online, mixedSeats, resume, transportVersion }
  create(configuration, operationId)
  join(invitation, guestIdentity, operationId)
  sendIntent(kind, payload, mutationId, expectedVersion, epoch)
  leave(reason)
  events: snapshotAccepted(snapshot), connectionChanged(state), failed(code)
```

كل event يحمل session generation. إغلاق الشاشة يلغي مالكية callbacks القديمة. snapshot يعدل الحالة المعتمدة؛ العرض يستمر من الموضع المرئي عبر `scene_motion.gd`. غياب خدمة شبكة لا ينشئ غرفة محلية مزيفة.

## قرارات الأونلاين

| الخيار | متى يناسب | النقص الذي لا يحله |
| --- | --- | --- |
| إبقاء Trystero في wrapper | إذا اجتاز POC وكان إبقاء الخدمات المجانية أولويّة | لا SLA، لا حجز عالمي ذري، لا host persistence، لا ضمان NAT |
| Godot WebRTC + `webrtc-native` | native مع شرط عدم وجود backend خاص | يلزم signaling متوافق وNostr/crypto إن أردنا البروتوكول نفسه، ونقل authority إلى GDScript؛ مجرد plugin غير كافٍ [S34] |
| خدمة WSS ذات سلطة مركزية | إذا اعتُمدت موثوقية أعلى وميزانية تشغيل | استضافة وأمان وتشغيل وخصوصية؛ تغيير بروتوكول الويب أيضًا، وليس تشغيل `/api/rooms` القديم |

**التوصية الحالية:** لا تبدل شرط الخدمات المجانية الموثق في المشروع من تلقاء نفسك. اختبر Trystero أولًا؛ إذا لم يحقق القبول عبر الشبكات، ارفع قرارًا موثقًا بين نطاق محلي فقط، أو TURN بإذن ميزانية، أو معمارية خادمية. لا تسجل الاتصال ناجحًا لتجاوز البوابة. TURN يحل relay للشبكات، ولا يحل بقاء سلطة المضيف بعد قتله [S35].

يجب تثبيت نسخة Trystero وقراءة وثائق **0.26.0** أثناء التنفيذ. مستودع Trystero الحالي قد يحتوي APIs أحدث من نسخة lockfile؛ لا تنقل مثال حديث مباشرة دون تحقق.

## التحصينات المطلوبة عند إبقاء P2P

- `epoch` + `mutationId` + version + seat ownership + allowlist للأوامر تظل إلزامية بالعقد الحالي. الاختبارات المشتركة تستخدم fixtures من القواعد الفعلية بين JS وGDScript.
- الرمز الثلاثي وسيلة تيسير؛ أضف موافقة المنشئ/أسماء جاهزة/سر دعوة طويل بحسب قرار نطاق السلامة. إطالة رمز بالواجهة وحدها لا تثبت حجزًا ذريًا عالميًا.
- `preview` يعرض أقل بيانات لازمة قبل القبول. لا تعرض هواتف أو رموز استعادة، ولا تضع token في رابط أو log.
- صف أول intent أثناء reconnect لا يصدر مرتين؛ لا تغير `expectedVersion` لحركة قديمة لتقبلها في دور جديد.
- المضيف يملك السلطة؛ هذا لا يمنع مضيفًا معدلًا من الغش. لا تدّع لعبة تنافسية مقاومة للغش أو تضف جوائز مالية مع هذه الثقة.
- قرار process death صريح: إلغاء مفهوم مع رسالة، أو تصميم استعادة حقيقي. لا يوجد في الكود الحالي ضمان استكمال غرفة المضيف بعد قتله.

## بناء حزمة محلية دون تغيير Pages

خطة مستقبلية: مرحلة staging تولد مجلدًا مستقلًا من `web/`، تختار PCK المشار إليه فعليًا من HTML/loader، وتحذف النسخة الزائدة بعد تحقق الترابط. لا تحذف PCK بالاسم تخمينًا. تحافظ على notices وتفصل debug fixtures عن release. لا تعدل `web/` الملتزم لمجرد أن wrapper يحتاج manifest، ولا تربط خدمة نشر ويب أخرى.

إذا اختير native: يبدأ task `YKL-029` بواجهة متكافئة وينتهي `YKL-030` بقرار شبكة، ثم تعاد بوابات الجوال نفسها؛ لا تستخدم نجاح wrapper كدليل للنسخة الأصلية. توحيد المخرجين في إصدار متجر واحد لا يلغي الحاجة لاختبار كل binary فعلي.
