# الاختبارات وبوابات السماح بالرفع

هذا **تصميم اختبار لاحق**. لم يُنفذ منه قبول تطبيق جوال في جولة البحث. قالب [acceptance-template.json](acceptance-template.json) يبدأ بنتائج `not_run`، ويحمل session/build/OS/evidence؛ لا يعاد استخدامه لتعديل سجل Pages القديم أو تحويله إلى passed.

## طبقات الأدلة

| الطبقة | ما تثبته | ما لا تثبته |
| --- | --- | --- |
| JSON/عقود JS | قانونية التحولات ومنع تكرار intent | عرض المحرك أو شبكة هاتفين |
| Godot headless | حالة المشهد والتحولات وإلغاء الحركات القديمة | لمس وأداء GPU وصوت على هاتف |
| browser contexts / محاكاة المقاس | DOM وبعض تفاعل المصدر | WKWebView binary أو جهاز مستقل |
| build مثبت فعليًا | سلوك الجهاز/OS/الحزمة المحددة | كل الأجهزة أو كل الشبكات |
| TestFlight/Play testing build | التوقيع والتوزيع وتجربة مرشح المتجر | موافقة الإنتاج تلقائيًا |

الاختبارات الموجودة ذات صلة: `game_rules_headless.gd`، `win_tutorial_headless.gd`، `scene_continuity_headless.gd`، `online_presentation_headless.gd`، `p2p_authority.test.mjs`، `p2p_mixed_timers.test.mjs`، `round_continue.test.mjs`، `reconnect_hydration_barrier_headless.gd`، واختبارات HUD/اللمس. اختَر ما يتعلق بالتعديل. بعض الاختبارات القديمة تتصل بمسار HTTP تاريخي؛ نجاحها لا يثبت Trystero ولا native.

## الحد الأدنى للأجهزة

| الحالة | الجهاز/النظام المقترح | الغرض |
| --- | --- | --- |
| أقدم iPhone مدعوم فعليًا | يحدد بعد toolchain، جهاز فعلي وشاشة صغيرة | أقل RAM وstartup وكيبورد |
| iPhone حديث مع safe area | iOS الحالي المقبول ومستوى OS آخر مدعوم | notch/جزيرة/حواف، 60/120Hz |
| أندرويد متوسط/اقتصادي | ARM64 وRAM3–4GB وشريحة GPU مختلفة | bottleneck/حرارة/دقة تكيفية |
| أندرويد حديث | Android16/API36؛ شاشة وإيماءات نظام | edge-to-edge والرجوع |
| بيئة 16KB | emulator/device مُثبت أنه يعمل بـ16KB | native libraries والتثبيت واللعب |
| iPad/tablet إذا وُزِّع عليه | جهاز فعلي ومقاس كبير | كاميرا ونصوص وحوارات وأداء |
| لعبة بين منصتين | iOS ↔ Android ثم منصة واحدة مع أخرى | توافق protocol وسلوك المضيف والضيف |

هذه أدوار اختبار وليست قائمة مشتريات. يسجل الجهاز المتاح ويحدد الاستثناء قبل النشر؛ لا يوضع OS أقل مما تدعمه الحزمة. عند استهداف iPhone فقط، اختبر كذلك نمط تشغيله المتاح على iPad إن كان المتجر يتيحه؛ لا تدّع دعم iPad محسن دون ذلك.

## سيناريوهات القبول

| IDs في القالب | السيناريو | دليل النجاح |
| --- | --- | --- |
| T01–T04 | تثبيت نظيف، أول تشغيل offline، الشرح، العودة للإعداد | لا شاشة انتظار شبكة للمحلي، شرح الفوز الثلاثي صحيح |
| T05–T08 | 2/3/4 لاعبين، بوتات مختلطة، اللوحة الممتلئة، 3/5 انتصارات | نفس عقد القواعد، لا تعارض ملكية |
| T09–T12 | برج/درج/سطر وحركة متعددة الأنماط، استمرار، rematch | اسم الفائز الحقيقي، لا إخفاء أحجار الفوز، الموافقات مرة واحدة |
| T13–T16 | ضغط سريع، التحديد، تغيير المقاس، كيبورد عربي | لا حركة مزدوجة، لا حجر محجوب أو نافذة خارج الشاشة |
| T17–T20 | الكاميرا/الرفع والهبوط/الإلغاء/reduced motion | استمرارية مرئية من الحالة الحالية، callbacks القديمة لا تغير الجديد |
| T21–T24 | قفل/خلفية/مكالمة/رجوع/قتل العملية | سياسة معلنة، لا صوت غير مطلوب أو تقدم خفي خاطئ |
| T25–T30 | إنشاء/دخول رابط/ألوان متزامنة/مقعد غير مملوك/reconnect/خروج مضيف | حالة متوافقة على جهازين، لا ادعاء استعادة غير موجودة |
| T31–T34 | شبكات مختلفة، رمز متعارض، abuse، flood/invalid input | فشل مفهوم أو نجاح مثبت، لا دمج غرف أو crash أو تسريب هوية |
| T35–T38 | الشبكة والخصوصية، مسح محلي، دعم/سياسة/رخص، صلاحيات | الإقرارات تطابق capture والنسخة، كل رابط عام يعمل |
| T39–T42 | startup/أداء/حرارة، 16KB، تثبيت متجر، تحديث/ترحيل | قياسات أصلية، release signing صحيح، لا فقد غير مبرر |

كل سيناريو online **مشروط بإدراجه في الإصدار**. يُستبعد بحالة `not_applicable` وسبب وقرار نطاق، لا بحالة نجاح. تتضمن T29 انقطاع الضيف قبل/بعد intent وتكراره بنفس mutationId، والعودة بعد 10/30/65 ثانية وفق مهلة النظام المعتمدة. تتضمن T30 فصل/قتل المضيف في وسط دور وموافقة جولة؛ الخروج الصريح مقبول إذا كان قرار المنتج، لا نهاية صامتة.

## عتبات داخلية مقترحة — ليست شروط المتجر الرقمية

| القياس | هدف أولي | منهج القياس |
| --- | --- | --- |
| feedback بدء التشغيل | صورة/تقدم مرئي خلال 2s | 5 تشغيلات باردة لكل جهاز، بوضع الطيران للمحلي |
| الوصول للإعداد | ≤10s على الحد الأدنى المختار | يشمل المقدمة المعتمدة؛ لا تغير توقيتها لإخفاء القياس |
| اللعب المستمر | median≥30FPS وp95 frame≤50ms | جلسة20 دقيقة، بعد warm-up، مع peak RAM/thermal |
| رد اللمس المحلي | p95≤150ms | من tap إلى feedback، على جهاز لا محاكاة |
| online | 20 محاولة ناجحة لكل زوج/مسار الشبكة المعتمد؛ join ضمن20s في الحالة السليمة | لا تعتبر نجاح relay وحده نجاح join؛ افصل الفشل/الإلغاء |
| انقطاع الشبكة | رسالة خلال مهلة محددة، لا انتظار بلا حد | loss/jitter/تبديل Wi-Fi↔cellular، مع تسجيل الحالة |
| الثبات | صفر crash/ANR/تجمّد متكرر في مصفوفة القبول | crash logs/native metrics + فيديو الأحداث |

إذا لم تتحقق عتبة داخلية، يسجل القرار: إصلاح أو تعديل الحد الأدنى أو تعديل نطاق التوزيع بالدليل. لا يوجد هنا ادعاء «متجر يشترط 30FPS» أو «20 محاولة تكفي لكل الشبكات». تجنب حفظ IP/هاتف/رموز سرية في evidence عام.

## البوابات

- **G0:** قرارات المنتج وحقوق التوزيع والحسابات معروفة، أو بنود لا تمنع تجربة داخلية موثقة.
- **G1:** route spike مثبت على الجهازين، اختير wrapper أو native بتقرير، لا بناء تجاري على route مجهول.
- **G2:** المحلي والقواعد والموشن والمدخلات ودورة الحياة مقبولة على route المختار.
- **G3:** data map وإقرارات وسياسة وسلامة وحقوق مكتملة. عند online، اتصال جهازين عبر المسارات المعتمدة مطلوب.
- **G4:** حزم موقعة وبيانات متجر وأدلة physical testing؛ Google closed testing عند انطباقه وطلب production access مكتمل، دون ضمان قبول.
- **G5:** نتيجة المراجعة الفعلية مقبولة، خطة دعم ووقف إصدار؛ النشر قرار مستقل عن نجاح بناء.

**ممنوع التمرير:** crash في first launch، شاشة سوداء، عجز عن إكمال مباراة، وظيفة مسوقة لا تعمل، بيانات/حقوق مجهولة، مشاكل لمس أساسية، أو online مُعلن بلا قبول أجهزة. لا تتجاوز أي بوابة بتغيير `blocked` إلى `passed` يدويًا.

## ماذا يشغّل المنفذ؟

بعد التعديل، يشغل العقود ذات الصلة والبناء المناسب ثم تحقق الجهاز والحزمة. لا يشغّل كل probes التاريخية بلا فهم، ولا ينشئ mocks ثم يسميها network acceptance. هذا التعديل الوثائقي يتحقق فقط من الخطة وروابطها المحلية وJSON وبصمات المصدر؛ لا حاجة لبناء اللعبة لإثبات سلامة Markdown.
