# Yakolak Developer D2 — Workbench Rationale

## المشكلة

نسخة D1 جمعت معرض البطاقات ومحرر الملاحظات ومركز مراجعات ووايت بورد ومعاينة اللعبة كنوافذ مستقلة فوق بعضها. النتيجة كانت تعدد مسارات العمل وتحميل معاينات كثيرة ونصوص تشرح الواجهة بدل أن تدعم المهمة الأساسية: مشاهدة التغيير واتخاذ قرار.

## القرار

D2 مساحة عمل واحدة بثلاث مناطق ثابتة على الكمبيوتر:

1. **التنقل**: المشاهد والعناصر وطابور المراجعات والبحث.
2. **المعاينة**: إطار حي واحد، إعادة، ملء شاشة، ومقارنة قبل/بعد.
3. **المراجعة**: الملاحظات، الردود، الحالات، والقرارات دون مغادرة المعاينة.

على الجوال تتحول المناطق الثلاث إلى تنقل سفلي، وتبقى المعاينة هي الشاشة الافتراضية.

## المراجع التصميمية

- Storybook: Sidebar + Canvas + Toolbar لعزل المكوّن أو المشهد موضع العمل.
- Chromatic UI Review: ربط القرار بالمقارنة البصرية وسجل المراجعة.
- Radix Primitives: إدارة التركيز ولوحة المفاتيح وخصائص ARIA.
- Rete.js v2 وReact Flow: مرجع لاتجاه تطوير مخطط المشاهد مستقبلًا.

## المكتبات

- **Lucide 1.27.0** مثبتة بإصدار محدد للأيقونات الواضحة والمتناسقة.
- **Drawflow 0.0.60** يبقى محمّلًا عند الطلب فقط للمحافظة على توافق المخططات الحالية. لا يدخل في مسار المعاينة الأساسي، وتوثق D2 أن ترحيله إلى Rete.js v2 مرحلة منفصلة حتى لا نخاطر ببيانات المخططات.

## مبادئ التنفيذ

- معاينة حية واحدة فقط بدل iframe لكل بطاقة.
- تحميل المقارنة والوايت بورد عند الطلب.
- نفس APIs ومخزن Turso الحالي دون كسر بيانات D1.
- مقارنة قبل/بعد على مستوى المشهد أو العنصر، لا على مستوى تعليق منفرد.
- واجهة بلا نصوص إرشادية طويلة؛ الحالات والأفعال تظهر وقت الحاجة.
- اختصارات: `R` لإعادة المعاينة، `C` للمقارنة، و`Ctrl/Cmd + K` للبحث.
