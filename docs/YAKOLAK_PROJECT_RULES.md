# Yakolak — قواعد ترتيب المشروع ومنع التخبيص

هذا الملف هو مرجع سريع لأي شخص أو مساعد يشتغل على المشروع.
الهدف: لا نعيد اختراع العجلة، ولا نكسر الثوابت التي تم الوصول لها بعد تعب.

---

## 1) قاعدة ذهبية

قبل أي تعديل:

1. اقرأ هذا الملف.
2. اقرأ `README.md`.
3. اقرأ ملف التشغيل الحالي: `src/app-prod-stage1.js`.
4. لا تستبدل عنصر موجود بعنصر جديد إلا إذا كان مفقودًا فعلًا.
5. لا تخترع خامة، حجم، مكان، أو عشوائية إذا كان لها أصل سابق في المشروع.

أي تعديل لازم يكون صغير وواضح: تغيير واحد في كل مرة.

## 4) أين أعدل؟

### الغرفة

في `src/app-prod-stage1.js`:

```txt
ROOM_CFG      أبعاد الغرفة
ROOM_LIMIT    حدود الكاميرا داخل الغرفة
addRoom()     إنشاء الأرض والسقف و 4 جدران والحواف والخطوط
```

قاعدة مهمة:

```txt
الغرفة هي بيئة فقط، لا تغير البورد ولا الطاولة ولا الانترو بسبب تعديل الغرفة.
```

### الطاولة

في `src/app-prod-stage1.js`:

```txt
TABLE_OBJ_URL        ملف الطاولة
TABLE_ALBEDO_URL     لون/خامة الطاولة الأصلية
TABLE_NORMAL_URL     تفاصيل سطح الطاولة
TABLE_ROUGHNESS_URL  خشونة الطاولة
TABLE_TOP_Y          مستوى سطح الطاولة
realTable()          تحميل الطاولة الأصلية
fallbackTable()      بديل فقط لو فشل الأصل
```

قاعدة مهمة:

```txt
أي تعديل على الطاولة يبدأ من realTable() و tableMaterial() فقط.
لا تكتب خامة جديدة إلا بعد التأكد أن الخامة الأصلية غير موجودة.
```

### البورد والقطع

في `src/app-prod-stage1.js`:

```txt
D      المسافة بين القطع = 48
R3     نصف قطر قواعد 3 = 135
A      أماكن البورد والقواعد النهائية
WALL   أماكن بداية جدران/قواعد الانترو
T      توقيتات الانترو
```

قاعدة مهمة:

```txt
لا تغير D / R3 / A / WALL / T إلا بطلب مباشر، لأنها ثوابت حساسة.
```

### الانترو

في `src/app-prod-stage1.js`:

```txt
lidAt()
wallAt()
pieceAt()
apply()
snap()
replay()
```

قاعدة مهمة:

```txt
الانترو يعمل فوق نفس الثوابت؛ لا تصنع انترو جديد إذا المطلوب تعديل غرفة أو خامة.
```

### الكاش والنسخ

```txt
index.html    BUILD العام في الصفحة
app.js        BUILD الذي يستدعي ملف اللعبة
version.json  build/version/note
```

قاعدة مهمة:

```txt
أي تعديل ظاهر للمستخدم لازم يرفع رقم BUILD في الثلاثة ملفات.
```

## 5) طريقة التعديل الصحيحة

عند أي طلب تطوير:

```txt
1. حدد العنصر المطلوب فقط.
2. ابحث في التاريخ أو الملفات عن النسخة التي كانت مزبوطة.
3. لا تخترع بديل إذا الأصل موجود.
4. عدل أصغر جزء ممكن.
5. ارفع BUILD.
6. اكتب في version.json ما الذي تغير بالضبط.
7. اختبر الرابط مع ?v=BUILD.
```

مثال:

```txt
طلب: خامة الطاولة غلط.
الصح: أرجع TABLE_ALBEDO / TABLE_NORMAL / TABLE_ROUGHNESS.
الغلط: أصنع CanvasTexture خشب من عندي.
```

- ممنوع إرجاع مشروع قديم كامل فوق الحالي بدون مقارنة.
