# Incremental Migration Plan

## قاعدة الانتقال

لا يتم نقل النسخة الحالية دفعة واحدة. كل Slice جديد يبنى داخل `vnext/`، يختبر مستقلًا، ثم يربط خلف Flag واضح. Production يبقى على المسار القديم حتى اكتمال شروط الاعتماد.

## المرحلة الحالية — Foundation

- [x] إنشاء مساحة مستقلة.
- [x] جرد الحالات والوضعيات.
- [x] تعريف الحدود المعمارية.
- [x] تسمية الحركات والكاميرات.
- [x] تعريف هيكل الاختبارات.
- [ ] اعتماد أول Slice للتنفيذ.

لا Runtime ولا UI جديد في هذه المرحلة.

## Slice 1 — Contracts فقط

ينشأ:

- Types/JSDoc لـ `Action`, `AppState`, `CameraPose`, `MotionRequest`.
- Reducer أو State Machine بلا Three.js.
- اختبارات انتقالات Boot → Entry → Mode.

شرط القبول: تشغيل الاختبارات دون متصفح ودون الاعتماد على ملفات النسخة القديمة.

## Slice 2 — قواعد اللعبة

ينقل من v126:

- اللوحة الفارغة.
- الحركات القانونية.
- المخزون.
- الفوز بثلاث طرق.
- التعادل.
- الدور القابل للعب.

شرط القبول: نفس نتائج اختبارات المحلي والأونلاين الحالية.

## Slice 3 — Camera Director

ينفذ Poses وحركات الكاميرا مستقلة عن اللعبة، مع Harness يعرض الجدار والطاولة وصندوقًا بديلًا للقطع.

شرط القبول: Desktop/Mobile/Reduced Motion، Resize، Recenter، ومقاطعة آمنة.

## Slice 4 — Input Router

يوحد Pointer/Touch/Mouse/Keyboard، ويفصل Tap عن Drag، ويصدر Actions فقط.

شرط القبول: لا إدخال مكرر، ولا تعارض بين سحب الكاميرا وسحب القطعة.

## Slice 5 — Clean Entry Journey

يبني Loader والجدار والقائمة والانتقال للطاولة فوق البنية الجديدة، دون إعداد أو لعب كامل.

شرط القبول: الرحلة تعمل منفردة وتعود للحالة الصحيحة عند Reload/Resize.

## Slice 6 — Setup

اختيار اللون والعدد والجولات عبر نفس State Machine، مع الاختلافات التي يحددها Mode فقط.

## Slice 7 — Local Match

دورة دور كاملة: اختيار حجم، حركة قانونية، وضع قطعة، انتقال دور، فوز وتعادل.

## Slice 8 — Bot

Bot adapter يستخدم Commands نفسها ولا يلمس المشهد مباشرة.

## Slice 9 — Online Session

ينقل الغرف المسماة والاستعادة والمزامنة إلى Network adapter، مع بقاء Game Rules مشتركة.

## Slice 10 — Results and Rematch

الجولات، النتائج، إعادة الجولة، المباراة الجديدة، والمغادرة.

## Slice 11 — Visual parity and replacement

مقارنة vNext بالنسخة الحالية، نقل الخامات والإضاءة الناجحة فقط، ثم تشغيل Flag تدريجي.

## مصادر ننقلها كمفاهيم لا كبنية

| المصدر | ما يستفاد منه |
|---|---|
| v112/v113 | تعليم أول حركة وإيقاف مؤقتها |
| v114–v118 | الخادم صاحب القرار والغرف والجولات |
| v115 | فصل كاميرا الإعداد عن اللعب |
| v117 | مسار لعب موحد محلي/أونلاين |
| v119 | علامة آخر حركة الهادئة |
| v120/v121 | سياسات وضوح الجوال والأداء |
| v122–v125 | رحلة الجدار والطاولة |
| v126 | الغرف المسماة والقواعد المشتركة |

## أشياء لا تُنقل

- سلسلة wrappers المتراكمة.
- runtime string replacement.
- Blob module bootstrapping.
- globals كعقود ربط.
- الاعتماد على DOM classes كمصدر للحالة.
- polling داخلي لملاحظة تغيرات محلية يمكن إصدار Events لها.

## شروط فتح Flag تجريبي

- قواعد متكافئة بالكامل.
- State transitions مغطاة.
- لا Runtime errors.
- أداء الجوال لا يقل عن النسخة الحالية.
- جميع الحالات الحرجة لها Recovery path.
- العودة للنسخة القديمة ممكنة دون تحويل بيانات دائم.
