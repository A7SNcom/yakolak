# Yakolak UX audit — 2026-07-29

## President direction

President Ahmad requested that Rashed identify user-experience problems in the game and have the team address them without changing Production, game rules, secrets, or human approval gates.

## Observed critical problem

The current v126 entry journey can end in a non-playable dead end:

- `index.html` force-hides the native entry, setup, HUD, online, tutorial, and settings surfaces with `display:none!important`.
- `src/entry-v126.js` hides `gameGroup` and disables pointer events on the renderer canvas.
- The journey completes without restoring either the game group, native setup surface, or canvas interaction.
- Bootstrap failures only recolor the loading star and update screen-reader-only text; there is no visible explanation or retry action.

## Management decision

Open one bounded task, `YAK-012-01`, to restore a playable handoff after the branded entry journey and provide a visible retry on startup failure. Reuse the native setup/game surfaces; do not create a parallel entry flow or alter game rules.

## Scope

Allowed implementation files:

- `index.html`
- `app.js`
- `src/entry-v126.js`
- `scripts/verify-v126-clean-entry.mjs`

## Acceptance

1. After the entry journey, the user can immediately reach the existing native game setup or game interaction.
2. The renderer canvas is interactive after handoff.
3. A startup failure shows a visible Arabic message and a retry action.
4. Reduced-motion users do not receive the full camera journey.
5. Desktop and mobile browser verification passes with no horizontal overflow.
6. No change to rules, networking contracts, Production, secrets, permissions, or approval gates.
